# ドライブ軌跡×動画同期アプリ 要件定義書

Oct 19, 2026 · @みや

## 概要・目的

ドライブの軌跡（GPX）を地図上に表示し、軌跡に沿って動く点とアクションカムの動画を同期再生するデスクトップアプリを作る。Windows・macOSの両方で動かす。

- 第1段階：軌跡を地図に表示し、点を時刻どおりに動かす
- 第2段階：点の位置に対応する動画を同時に再生する
- 狙い：スマホのGPSログと、別機材で撮った動画を組み合わせて、ドライブ全体を振り返れるようにする

## 前提・入力データ

軌跡はスマホアプリ（RouteHistory）のGPX、動画はアクションカムの映像で、両者は別々の機材で記録される。

| データ | 形式 | 内容 | 備考 |
| --- | --- | --- | --- |
| 軌跡 | .gpx / .xml（中身は同じ GPX 1.1） | trk > trkseg > trkpt（lat, lon, time, ele） | time は UTC。trkseg が複数ある場合は1本に連結する |
| 動画 | アクションカムの動画ファイル（mp4 想定） | 映像・音声、撮影開始時刻のメタデータ | 1回のドライブで複数クリップに分かれる想定 |

- 動画の撮影開始時刻は、ファイルのメタデータ（creation\_time）から取得する前提とする
- アクションカムの時計はずれていることがあるため、GPXの時刻と完全には一致しない前提で設計する

### 実機データで確認したこと（2026-10-19）

手持ちのサンプル（`original/` の GPX 1本と動画1本）を実際に調べた結果、次のことが確定した。

| 項目 | 確認結果 |
| --- | --- |
| カメラ | DJI Osmo Action 4 |
| 動画の形式 | **HEVC（H.265）Main 10 / 10bit**、1920×1080、29.97fps、約32Mbps |
| 動画の長さ・サイズ | 7分23秒で 1.79GB（1日分で数十GBになる） |
| creation\_time | **UTC で記録されている**。`2026-09-25T07:04:45Z` に対しファイル名は `20260925160437`（16:04:37 JST）で、差はちょうど9時間 |
| 動画内のGPS | **なし**。Osmo Action 4 はGPS受信機を内蔵しないため、GPXが必須 |
| GPXのサンプル | 16,303点、約9時間、trksegは1本。点の間隔は中央値1秒・95%が2秒以内 |
| GPXの欠損 | **60秒以上の空白が58箇所、300秒以上が11箇所、最大1,385秒（約23分）** |
| 両者の時刻関係 | 動画区間（07:04:45Z〜07:12:08Z）はGPXの範囲に完全に含まれ、該当区間に294点ある |

- creation\_time がUTCと分かったため、懸念していた「9時間ずれ」は起きない。ただし他機種では異なる可能性があるため、読み込み側ではUTCとして扱い、ずれはフェーズ3の手動オフセットで吸収する
- 動画にGPSが入っていないことが確定したので、「将来GPXなしで動かす」案はこの機材では成立しない

## 機能要件

3つのフェーズで進め、同期は「動画→地図」の一方向から始める。動画の再生位置から地図の点を決める方向は、フェーズ1の補間処理をそのまま使えるため最も簡単。

| フェーズ | 機能 | 内容 |
| --- | --- | --- |
| 1 | GPX読み込み | .gpx / .xml をファイル選択またはドラッグ&ドロップで読み込む |
| 1 | 軌跡表示 | 全ルートを薄い線で表示し、範囲に合わせて地図をズームする |
| 1 | 点のアニメーション | GPXの時刻に沿って点を動かし、走行済みの軌跡を濃い線で伸ばす |
| 1 | 再生操作 | 再生・一時停止・再生倍率の切り替え |
| 2 | 動画読み込み | 複数の動画クリップを読み込み、撮影開始時刻を取得する |
| 2 | 動画区間の表示 | 動画がある区間を軌跡上で色分けする |
| 2 | 動画→地図の同期 | 動画の再生位置から時刻を求め、地図の点をその位置に動かす |
| 2 | 区間の切り替え | 動画のない区間は点だけを倍速で進め、動画区間に入ったら等速で動画を再生する |
| 3 | 地図→動画の同期 | 軌跡をクリックすると、最寄りの地点の時刻へ動画をシークする |
| 3 | 時刻ずれの補正 | 動画ごとに時刻のオフセット（秒）を手動で調整し、保存する |
| 3 | シークバー | ドライブ全体のタイムラインで再生位置を操作する |

## 非機能要件

- 対象OS：Windows・macOS
- 動画コーデック：H.264は必須で対応する。手持ちの動画は **HEVC（H.265）の10bit** であることが確定したため、これを再生できるかどうかが最大の技術リスクになる（詳細は「動画コーデックとデスクトップ化のリスク」を参照）
- 性能：数万点のGPXでも、点のアニメーションがカクつかないこと
- 動作環境：ローカルファイルだけで完結し、サーバーやアカウントを必要としない
- 地図：背景地図のタイルはネット接続を前提とする（オフライン対応は将来の検討事項）
- 動画データの扱い：1ファイルで数GBあり、GitHubの1ファイル100MB制限を超えるため、動画はリポジトリに含めず `.gitignore` で除外する。ローカルの元データを参照する

## 技術選定・開発方針

まずブラウザで動くJavaScriptとして実装し、動いた段階でTauriかElectronで包む。地図はMapLibre GL JS、開発サーバーはViteを使う。

1. ブラウザ版を作る：GPX読み込み、軌跡表示、アニメーション、動画の同期まで、ブラウザで完結させる
2. OSに依存する処理を分離する：ファイルの読み込みと動画メタデータの取得は、専用のモジュールに閉じ込める。ブラウザ版はファイル選択とドラッグ&ドロップ、デスクトップ版はネイティブのダイアログに差し替える
3. ChromeとSafariの両方で確認する：Tauriは、WindowsではChromium系（WebView2）、macOSではSafari系（WKWebView）で動くため、両方で動くことを先に確かめておく
4. デスクトップ化する：TauriかElectronを選び、ファイルアクセスの部分だけを差し替える

| 項目 | Tauri | Electron |
| --- | --- | --- |
| 描画エンジン | OS標準のWebView（Windowsと macOSで異なる） | Chromiumを同梱（どのOSでも同じ） |
| アプリのサイズ | 小さい（数MB〜） | 大きい（100MB前後） |
| ネイティブ側の言語 | Rust | Node.js |
| 動画再生の挙動 | OSごとに差が出る可能性がある | OS間で揃いやすい |

- 動画の撮影開始時刻は、ブラウザ版ではmp4box.jsなどでmp4のヘッダーから読む。デスクトップ版ではffprobeを同梱する方法も選べる

## 動画コーデックとデスクトップ化のリスク

このプロジェクトで最も大きな技術リスクなので、前提から順に整理しておく。

### コーデックとは

動画ファイルは、映像をそのまま保存すると巨大になるため、必ず圧縮して保存されている。この圧縮方式のことをコーデックと呼ぶ。再生する側は、同じ方式を知っていないと映像を元に戻せない。

- **H.264（AVC）** … 2003年からある方式。古いぶん、どの機械・どのソフトでもまず再生できる
- **H.265（HEVC）** … H.264の後継。同じ画質なら**ファイルサイズが半分ほどで済む**代わりに、**特許の扱いが複雑で、再生できる環境が限られる**

手持ちの動画は後者のHEVC。しかもHEVCの中でも「10bit（Main 10）」という、色の階調をより細かく持つ形式になっている。これは対応環境がさらに狭い。

### なぜブラウザでHEVCが再生できないことがあるのか

HTMLの `<video>` タグは、ブラウザが自力ですべてのコーデックを再生しているわけではない。H.264のように広く使われる方式はブラウザ自身が再生機能を持っているが、**HEVCについてはブラウザは再生機能を自前で持たず、OSが持っている再生機能を借りて動く**。特許のライセンス料が高く、ブラウザに組み込んで無償配布するのが難しいためである。

つまりHEVCが再生できるかどうかは、「ブラウザが何か」ではなく「**そのOSにHEVCの再生機能が入っているか**」でほぼ決まる。

| 環境 | HEVCの再生 |
| --- | --- |
| macOS（Safari / Chrome とも） | OSが標準で持っているため、基本的に再生できる |
| Windows（Chrome / Edge とも） | OSに標準では入っていない。Microsoftストアの「HEVCビデオ拡張機能」（有料・約120円）を各ユーザーが自分で入れる必要がある |
| 10bit（Main 10） | 上記に加えて対応状況がさらに限られ、環境によっては再生できない |

macOSでは問題なく動いて、Windowsに持っていくと「音は出るが映像が真っ黒」という形で表面化しやすい。macOSだけで開発を進めると最後まで気づけない種類の問題である。

### TauriとElectronの違いが、ここに効いてくる

どちらも「Webの技術で作った画面を、デスクトップアプリとして動かすための仕組み」である。違いは**画面を描く部品（WebView）をどこから持ってくるか**。

- **Tauri** … OSに最初から入っているWebViewを借りる。Windowsでは WebView2（Chromeと同じ中身）、macOSでは WKWebView（Safariと同じ中身）。**OSごとに中身が違う**ので、同じコードでも挙動が変わりうる。そのぶんアプリは数MBと軽い
- **Electron** … Chromium（Chromeの中身）をアプリに丸ごと同梱する。**どのOSでも中身が同じ**なので挙動が揃いやすい。そのぶんアプリは100MB前後と重い

ここで重要なのは、**Electronを選んでも、HEVCの問題は解決しないということ**。Electronが同梱するのはChromium本体であって、HEVCの再生機能はやはりOSから借りるためである。Electronの「挙動が揃う」という利点は、**HEVCに関しては効かない**。

> つまり：TauriとElectronのどちらを選ぶかという判断より先に、**HEVCをどう扱うかを決める必要がある**。コーデックの問題は、デスクトップ化の方式を変えても回避できない。

### 取りうる対策

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A. カメラ側をH.264で撮る | Osmo Action 4 の設定で記録形式をH.264に変更する | **最も簡単。今後の撮影には有効だが、撮影済みの動画は救えない** |
| B. 取り込み時にH.264へ変換する | アプリに読み込む前後で、ffmpegを使ってH.264に変換する | 確実に再生できるようになるが、変換に時間がかかり、ディスクも二重に必要 |
| C. Windowsユーザーに拡張機能を入れてもらう | 「HEVCビデオ拡張機能」の導入を前提にする | 自分だけで使うなら現実的。配布するなら手順の案内が必須 |
| D. 動画のデコードを自前でやる | アプリ内にffmpegを同梱して自前で再生する | 技術的には可能だが、作る量が大きく増える |

当面は **「自分のmacOSで動かす」ことを優先し、A案（今後はH.264で撮影）とC案（Windowsでは拡張機能）を基本線とする**。B案はフェーズ2以降で、必要になった時点で検討する。

### 最初に確かめること

ブラウザ版の実装に入る前に、**手持ちのHEVC 10bit動画が `<video>` タグで再生できるかを、最小のHTMLで確認する**。確認する順番は次のとおり。

1. macOSのSafariで再生できるか
2. macOSのChromeで再生できるか
3. （可能なら）WindowsのEdge / Chromeで再生できるか

ここで再生できない場合、フェーズ2の設計そのものが変わるため、最優先で潰しておく。

## 競合と差別化

既存のソフトはドラレコ専用で、映像に埋め込まれたGPSを読むものが中心。別機材のGPXと複数の動画を組み合わせる用途にぴったり合うものは少ない。

| ソフト | 種類 | 特徴 |
| --- | --- | --- |
| [Dashcam Viewer](https://dashcamtalk.com/forum/threads/dashcam-viewer-for-mac-and-windows.4357/post-510528) | Windows / Mac、無料版あり | GPX読み込みと時刻ずれ補正に対応。無料版は動画2本まで。最も近い競合 |
| [NovaTrakt](https://alternativeto.net/software/dashcam-viewer) | Windows、無料・OSS | ドラレコ向けのGPS動画プレーヤー |
| [dashcamigo](https://dashcamtalk.com/forum/threads/dashcamigo-free-dashcam-viewer-that-runs-in-the-browser.61341/) | ブラウザ、無料 | 前・後・車内カメラを1本のタイムラインで同期 |
| [GPX Player](https://api.openstreetmap.org/user/roguish/diary/42093) | デスクトップ | 動画とGPSログを並べて再生。2017年の紹介記事で、現状は不明 |
| [GPX Animator](https://mynixos.com/nixpkgs/package/gpx-animator) | CLI / デスクトップ | GPXから軌跡の動画を生成するのみ。動画との同期はなし |

差別化のポイント：

- GPXと動画が別の機材でも、撮影時刻で自動的に軌跡上に配置できる
- MapLibreで国土地理院タイルやベクトルタイルを自由に使える（既存ソフトはGoogle Maps依存が多い）
- 動画のない区間は早送り、動画区間は等速再生という、ドライブ全体を振り返る体験
